## Handoff: Bug terminali neri in Traflix Space

### Contesto
App desktop Tauri 2 + React 19 + Rust. I terminali (xterm.js + ConPTY) si avviano correttamente lato Rust ma restano neri e non mostrano output. I PTY vengono creati e killati ciclicamente ogni ~5-20 secondi.

### Root cause identificata

In `src/components/workspace/WorkspaceView.tsx` esistono due sistemi paralleli che producono `displayTerminals`:

- **Path A**: `configTerminals` — array caricato da `invoke("get_workspace")`, disponibile subito
- **Path B**: `workspaceTerminals` — array dallo `terminalStore` Zustand, popolato da `terminalHook.create()`

Il `useMemo` di `displayTerminals` switcha tra i due in base a `hasStoreTerminals`:

```ts
const displayTerminals = useMemo(() => {
  if (hasStoreTerminals) {
    return workspaceTerminals.map(...)  // Path B
  }
  return configTerminals.map(...)       // Path A
}, [hasStoreTerminals, workspaceTerminals, configTerminals]);
```

**Sequenza del bug:**
1. Primo render: `hasStoreTerminals = false` → usa Path A → monta `TerminalPane` → `XTermWrapper` chiama `create_pty` → PowerShell parte
2. Il secondo `useEffect` chiama `terminalHook.create()` per ogni terminale → popola lo store
3. `hasStoreTerminals` diventa `true` → `displayTerminals` cambia → React rimonta tutti i `TerminalPane`
4. `XTermWrapper` cleanup → `kill_pty` → PowerShell killato
5. Nuovo mount → nuovo `create_pty` → ma ora si ripete il ciclo

Confermato dai log Rust: ogni ciclo crea PTY, li killa ~10-20 secondi dopo, li ricrea, li killa di nuovo. I terminali restano neri perché vengono sempre distrutti prima che l'utente veda qualcosa.

### Fix

**Eliminare il doppio sistema.** `WorkspaceView` non deve mai popolare lo store tramite `terminalHook.create()` — lo store è ridondante se `configTerminals` contiene già tutto il necessario (id, shell, cwd, agentId).

**Approccio concreto:**

1. **Rimuovere** il secondo `useEffect` in `WorkspaceView` (quello che chiama `terminalHook.create()` in loop)
2. **Rimuovere** tutta la logica `hasStoreTerminals` / `workspaceTerminals` / `displayTerminals` con il branch
3. **Passare `configTerminals` direttamente** a `WorkspaceGrid` come `displayTerminals`, senza passare per lo store
4. Lo store Zustand va usato **solo** per stato UI runtime (quale terminale è attivo, titolo dinamico) — non come fonte di verità per quali terminali esistono

```tsx
// WorkspaceView semplificato
useEffect(() => {
  if (!activeWorkspaceId) { setConfigTerminals([]); return; }
  invoke("get_workspace", { id: activeWorkspaceId })
    .then((cfg) => setConfigTerminals(cfg.terminals || []))
    .catch(...);
}, [activeWorkspaceId]);

// Niente terminalHook.create(), niente hasStoreTerminals
// displayTerminals = configTerminals direttamente
<WorkspaceGrid
  rows={workspace.layout.rows}
  cols={workspace.layout.cols}
  terminals={configTerminals}
/>
```

5. In `WorkspaceGrid` e `TerminalPane` assicurarsi che la `key` dei `TerminalPane` sia sempre `term.id` (già così) — questo garantisce che React non rimonta i pane se l'array non cambia referenza inutilmente

6. Il `terminalStore` può restare per `activeTerminalId` e `updateTerminalTitle`, ma `createTerminal` non deve più essere chiamato da `WorkspaceView`
