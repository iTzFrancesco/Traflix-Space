## Correzioni approvate dall'utente (prima dell'esecuzione)

1. **C4**: `ephemeral: true` per i thread Jarvis (thread/start effimero, nessun rollout su disco; se App Server crasha → ricrea thread dalla memoria Jarvis). `1 ephemeral thread/workspace`, nuovo thread su Clear Conversation, nessun thread persistito tra riavvii.
2. **C5/C6**: Dynamic Tools **namespaced** (`namespace` + `tool`, App Server impone `^[a-zA-Z0-9_-]+$` sul nome): `workspace.overview`→ns=workspace/tool=overview, `terminal.list`→ns=terminal/tool=list, `agent.list|status|last_result|activity|tail`→ns=agent, `markdown.read`→ns=markdown/tool=read, `ui.open_terminal`→ns=ui/tool=open_terminal, `conversational.plan`→ns=conversational/tool=plan. `item/tool/call` restituisce namespace+tool.
3. **C5**: togliere `MAX_TOOL_ROUNDS` ma tenere limiti lato host: `MAX_DYNAMIC_TOOL_CALLS_PER_TURN = 12`, `MAX_SIDE_EFFECT_PLANS_PER_TURN = 1`, `TURN_DEADLINE = 90–120s`.
4. **C7**: NON esiste `phase: commentary|final_answer` in agentMessage. Regola UI: ogni `agentMessage` completato mostrato subito; se dopo arriva un tool era un aggiornamento intermedio; **l'ultimo agentMessage prima di `turn/completed` è il final**; `reasoning` sempre ignorato.
5. **C3**: usage/rateLimits letti esclusivamente da App Server; gli update `account/rateLimits/updated` sono incrementali → merge con ultimo snapshot (o ri-lettura `rateLimits/read`), MAI sovrascrivere campi mancanti con `null`. Ordine dei reasoning dal catalogo `model/list`, non inventato lato UI.

**C10**: "nessun riferimento Zen residuo" = nessun riferimento a **OpenCode Zen come provider di Jarvis**. `OpenCode` come agente PTY nei terminali RIMANE (Jarvis deve poter fare `agent_open(provider="opencode")`).
